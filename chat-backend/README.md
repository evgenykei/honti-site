# Чат сайта ХОНТИ

Статический виджет + Yandex Cloud Function (Python 3.12) + YDB Serverless.
Посетитель пишет и читает ответы на сайте. Оператор получает уведомления в личных
диалогах Telegram/MAX и отвечает штатной функцией «Ответить». Резервная команда:
`/reply <идентификатор из уведомления> текст`. Поддерживается текст до 2000 символов.
Вложения, редактирование и удаление сообщений пока не поддерживаются.

## Текущее состояние

Код подготовлен; облачные ресурсы, реальные токены и Webhook ещё не подключены.
`assets/chat-config.js` содержит пустой API URL: до завершения настройки виджет
показывает реальные контакты и не имитирует отправку сообщений.

## Развёртывание

1. В каталоге `b1gmnlvem2m5tl90cut6` создать **YDB Serverless**, выполнить `schema.sql`.
2. Создать отдельный сервисный аккаунт. Дать ему `ydb.editor` только на эту базу,
   назначить аккаунт функции. Постоянный ключ аккаунта не нужен: SDK использует
   metadata credentials. Установить ограничения потребления YDB и бюджетные уведомления.
3. Архивировать файлы `core.py`, `index.py`, `storage.py`, `requirements.txt` в корне ZIP.
   Создать Cloud Function Python 3.12, `index.handler`, 128 МБ, таймаут 30 секунд,
   не более одного экземпляра на начальном запуске. Не включать логирование тела
   HTTP-запросов. Для публичного вызова нужна роль `functions.functionInvoker`
   для `allUsers` **только на эту функцию**.
4. Указать `YDB_ENDPOINT`, `YDB_DATABASE`, `CHAT_ORIGIN=https://honti-it.ru`.
   Внести секреты непосредственно в Cloud/Lockbox:
   `RATE_SALT` (случайные 32+ байта), `TELEGRAM_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`,
   `MAX_TOKEN`, `MAX_WEBHOOK_SECRET`.
   Указать числовые `TELEGRAM_OWNER_ID` и `MAX_OWNER_ID` владельца.
   Канал активен только при наличии всех трёх параметров TOKEN/OWNER_ID/WEBHOOK_SECRET.
   Токены в GitHub, JS, команды с явными значениями, скриншоты и чат не помещать.
5. Оператор должен нажать Start у обоих ботов из своего личного профиля.
   Его ID получить из события `bot_started`/`message` через доверенную локальную
   проверку API. Не разрешать автоматическое назначение первого посетителя владельцем.
6. Для Telegram вызвать `setWebhook`, URL функции с `?action=telegram`,
   `secret_token=TELEGRAM_WEBHOOK_SECRET`, `allowed_updates=["message"]`.
   Для MAX вызвать `POST https://platform-api2.max.ru/subscriptions`, передать
   URL с `?action=max`, `update_types=["message_created"]`, `secret=MAX_WEBHOOK_SECRET`.
   Авторизация MAX — заголовок `Authorization`, не query string.
   Для MAX проверить доверие сертификату по официальной документации. Если нужен
   дополнительный корневой сертификат, включить **проверенный** CA bundle в архив
   и задать `MAX_CA_FILE`; проверку TLS не отключать.
7. После проверки API записать публичный URL функции без query string в
   `assets/chat-config.js`. Проверить HTTPS, CORS, оба канала, ответы двум
   независимым посетителям, повторную отправку и обновление страницы.
8. Публиковать через PR. Не включать виджет с рабочим endpoint до проверки
   обоих операторских ID и секретов Webhook.

## Хранение и ограничения

История доступна 7 дней; TTL удаляет записи асинхронно, проверка срока работает
также в приложении. Секрет сессии хранится в sessionStorage вкладки, на сервере —
его SHA-256. IP хранится только как HMAC со случайной серверной солью.
История одного чата — максимум 200 сообщений. Новых чатов: 5/час на IP,
100/час суммарно. Сообщений: 60/мин суммарно, не чаще одного в 3 секунды на чат.
Проверка истории каждые 15 секунд только при открытом чате и видимой вкладке.
Бесплатные квоты **не являются жёстким потолком расходов**: публичный endpoint
может получать запросы до проверки приложением. Перед запуском установить
облачные ограничения/бюджет и проверить актуальные тарифы.

Уведомление отправляется после сохранения сообщения. При сбое отправки оно
повторяется при следующем запросе истории или повторной отправке посетителя.
Если он закроет окно сразу после сбоя, уведомление останется в очереди до
следующего обращения в эту сессию. Для гарантированной фоновой доставки нужен
отдельный триггер/outbox worker; в первой версии его нет. Сбой между отправкой
во внешний API и сохранением результата может привести к повторному уведомлению,
но не к дублированию сообщения в истории сайта.

## Проверка

`cd chat-backend && python -m unittest -v`

Тесты выполняются без облака и не отправляют сообщения. Они проверяют изоляцию
сессий, повторные запросы, сроки, лимиты, маршрутизацию, секрет Webhook и владельца.
Отдельно обязательна проверка на реальных YDB/Telegram/MAX перед публикацией:
локальные тесты не подтверждают настройку облака и внешних API.
